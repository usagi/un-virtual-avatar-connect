# UNシリーズの公開確認

対象はUNVAC v2、UNAvatar、UNMotion。機能を減らして操作を簡単に見せることは合格条件にしない。
個人環境で候補版を使い始められること、一般公開に必要な確認が済んだこと、実際に公開する承認を
得たことを区別する。

## 確認する利用経路

| 利用経路 | 確認する結果 | 合格の根拠にしないもの |
|---|---|---|
| AIを使わずTwitch配信を支援する | 初回用途選択、接続フォーム、認証、用途追加から実イベントの処理・チャットや画面への出力まで辿れる | 模擬認証、画面が開くだけの確認 |
| AI共演者を使う | 接続・音声・画面取得元・返答・字幕・身体表現が選択した相手につながる。AIなし構成にも戻せる | AI設定項目の存在、入力受付だけ |
| 高度なFlowgraphを編集する | 全構成、参照先、編集、保存、適用、処理状態、共有・取込、依存を考慮した撤去・復元に到達できる | ノード名の一覧、保存と実行の同一視 |
| 複数VAC・複数プロファイルを使う | 編集対象、稼働個体、次回起動の指定を識別できる。別対象に設定が波及しない | 単一プロファイルだけの操作 |
| Avatarを表示・調整する | モデル・衣装・表情・入力・カメラ・外観・物理・出力の既存入口を保持する。保存値と稼働個体への反映を区別できる | 目次の存在、モデルなしの描画確認だけ |
| Motionを取得・調整・送信する | 入力方式別設定、補正、平滑化、保持、出力、複数Capturerの対象と状態が追える | 模擬フレームだけで実カメラの滑らかさを保証すること |
| 保存に失敗する・設定が壊れる | 入力が保持され、競合を拒否し、再読込・破棄・再保存・復元を選べる。再起動後も意図した内容になる | 正常保存だけ、試験器が模倣したエラーだけ |

## 機能保持と画面

旧機能から新しい入口までを対応付ける。各行で、対象、表示条件、保存先、稼働中への反映か
次回起動への反映かを記録する。動的な衣装・物理分類・入力方式、ファイル選択、ネイティブメニューも
対象とし、静的なコマンド一覧だけで全機能保持の合格を付けない。

採用済みのレイアウト・意匠を使う。一般ユーザーが用途から入れることと、熟練者が全機能へ
直接辿れることを両立し、狭い画面でも対象表示と編集操作を失わない。大きな構成変更が必要なら、
同じ機能を備えた操作可能な比較サンプルを先に提示する。

## 証拠の分け方

- ソース照合：機能・分岐・保存経路の存在を示す。操作成功の証明とはしない。
- 模擬環境：配置、入力保持、分岐を確認する。実サービス・実機の成功とはしない。
- 隔離した通常版：保存、再起動、対象分離、実行中個体への反映を確認する。
- 実環境：カメラ、OBS、Twitch、配信時の負荷と会話の間合いを確認する。
- 見た目：身体表現の連続動画、表情と口パク・瞬きの共存を確認する。角度一致だけで自然と判定しない。

各証拠には実行ファイルの識別情報、設定、日時、実施操作、結果、未確認範囲を結び付ける。
変更箇所と関係しない検証を理由なく繰り返さない。新しい長尺VODを必須にせず、保存済みログ・画像・
短い確認で足りる範囲はそれを用いる。AIの完全な正答を要求して無限に改善し続けるのではなく、
選択した取得元・返答直前の画像・条件付き履歴という契約と、具体的な実用上の問題を評価する。

## 配布・移行・復元

通常名のEXE、必要なDLL、モデル・入力エンジンの同梱範囲、導入案内、ライセンス情報を照合する。
個人の資格情報・配信設定・モデルを公開物に混入させない。更新前の退避、更新後の内容照合、
変更されたファイルを勝手に上書きしない復元手順を用意する。複数回更新した場合は逆順に戻す。

この文書は公開判定の基準であり、同梱されているだけで確認完了を意味しない。
各版の確認結果・未確認範囲は、その版のリリース案内で示す。
個別試験が成功していても、上記経路・機能保持・実環境の未確認項目を自動的に合格へ変更しない。
実配信構成の詳細は[UNVACの実配信確認](v2-release-gate.md)を参照する。

## モード・連携アプリの変更時に追加する確認

- 通常の1個体では主要メニューを管理情報より先に表示し、複数個体は必要なときに対象を確認できる。設定ファイル指定なしの再起動操作は既存ウィンドウを表示し、明示設定による別個体起動は保持する。
- モードは設定から生成する。2個に固定せず、未定義、3個以上、長い表示名、狭幅での到達性と現在モードの表示を確認する。編集するモードを選んでも稼働モードは切り替わらない。
- 複数アプリの詳細・新規登録・モード操作を同じ下書きとして扱い、画面や編集対象の切替で失わない。確認キャンセルでは保存せず、明示破棄で全対象の下書きを破棄する。
- 一括保存は全件を検証してから書き込む。後半の不正入力、重複ID、保存競合ではファイル全体を維持する。保存だけで連携アプリを起動・終了しない。再起動後の読込とバックアップ復元も確認する。
- VAC終了時と手動・モード切替による終了要求の方針を区別する。既存の終了方式・待機時間・アプリ固有処理は保持する。登録したプロセス名がどの稼働個体に一致するか、他のVACとの共有状況は、隔離試験と実運用で分けて確認する。
- 配布用の内蔵GUIは、開発用gui/distを参照できない設定でも動作し、配信された画面資産が検証対象のビルド入力と一致することを確認する。開発用CLIと外部画面だけの成功で代用しない。

# Quickstart — 使いたい機能から始める

このドキュメントは **v2 配布物を新規に動かす**手順です。v1からの移行は [移行手順](v1-to-v2-migration.md) を先に確認してください。

## 最初に、使いたいことを選ぶ

最初から全機能を設定する必要はありません。AIなしの通知・クリップ紹介なら、AIパートナーやマイク、アバターの準備は不要です。配布物の起動に必要なものを次の節で確認した後、以下を入口にしてください。

| やりたいこと | 最初の操作 | 続けて確認するもの |
|---|---|---|
| Twitchの通知・クリップ紹介を使う | 初回画面で「Twitch配信支援（AIなし）」を選ぶ | [Twitch接続とOBSへの表示](#twitch配信支援から始めるaiなし) |
| 使っている構成へ機能を足す | 左の「機能を探す」で「用途から機能を追加」を開く | 追加済みの一覧、必要な接続先、追加内容 |
| 自分の処理を組む・細かく変更する | 「Flowgraphの編集・共有」を開く | Studioで構成ファイル、ノード、接続を編集する |
| AI共演者を使う | 配信AIの構成を作り、「AIの導入・基本設定」を開く | モデル・認証情報・観測対象。AIの利用だけでアバター表示が必須になるわけではない |
| プロファイルを追加・複製・削除・復元する | 「保存プロファイル管理」を開く | 対象名と保存先。起動や実行先の切替とは区別する |
| いつもの配信を始める | ホームで操作対象、動作モード、入力とAIの状態を確認する | 必要に応じて「配信前の動作確認」で出力を試す |

表の機能名は「機能を探す」の目次と同じです。場所が分からない場合は、その名前で検索できます。テンプレートから始めた構成も通常のFlowgraphとして編集できるため、後から独自の処理を追加できます。

### 複数のVACやプロファイルを使うとき

- **操作中のVAC**は、この画面が接続している実行中のアプリです。モードや入力の受付を変える前に、画面上部の対象を確認します。
- **保存プロファイル**は、設定と関連ファイルのまとまりです。管理画面で選ぶことや複製することだけでは、稼働中のVACは切り替わりません。
- **次回起動の指定**は、次に起動するときに開く対象です。すでに動いている別VACへの反映とは別です。

保存後は「適用待ち」「再起動が必要」などの結果も確認します。同じ保存先や認証情報を共有する範囲は、各操作の説明に従ってください。設定を独立させたい場合は、EXEを別フォルダーに置くだけではなく保存先も分ける必要があります。

## 1. 用意するもの

Windows向け配布物を展開し、同梱の `virtual-avatar-connect-desktop.exe` を起動します。利用するだけならRustやNode.js、ソースのビルドは不要です。同梱ファイルを残したまま展開先から起動してください。ソースから試す場合は末尾の開発者向け手順を参照してください。

デスクトップの設定画面には **Microsoft Edge WebView2 Runtime** も必要です。通常はWindowsに導入済みですが、未導入・破損している環境では設定画面を開けません。[Microsoft公式のWebView2配布ページ](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section)からEvergreen Runtimeを導入し、アプリを起動し直してください。Edgeブラウザー本体とは別の実行環境です。詳しくは[Microsoftの配布説明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)を参照してください。

現在のWindows版は、本体と音声処理workerの実行に **Microsoft Visual C++ v14 Redistributable（x64）** を必要とします。Whisperを使わない場合も対象です。`MSVCP140.dll`、`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll` がないというエラーが出る場合は、[Microsoft公式の配布ページ](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/)からx64版を導入してください。ビルドに使ったツールより古いRuntimeでは不足する場合があるため、公式の最新サポート版を使います。

Vulkanを利用できない環境ではCPU版へ切り替わりますが、共通のVC++ Runtime不足はCPUへの切替では解消しません。配布候補のクリーン環境での確認は継続中です。

通知・チャット・クリップ紹介だけなら、AI契約・API key・マイク・アバターは不要です。画面へ表示する場合はOBS Studio、音声を使う場合は選んだ音声エンジンも用意します。

VACの音声出力デバイスは最初に音声を再生するときに開きます。通知や設定編集だけの起動では不要です。
再生時に出力デバイスを開けなければ音声処理がエラーになり、次の再生で再試行します。

> この案内は開発中v2のソースに対応します。比較用UIの採用や配布物の公開完了を示すものではありません。

## 2. 初回起動

```powershell
.\virtual-avatar-connect-desktop.exe
```

引数なしの desktop 版は、OS のユーザープロファイルストア（Windowsでは `%APPDATA%\UN Virtual Avatar Connect\profiles\`）からactive profileを開きます。初回は安全なstarter profileを作成し、Windowsの動的ポート予約と衝突しにくい `127.0.0.1:46000` でGUIを表示します。GUIを閉じた後もtrayへ常駐します。portable運用や開発で既存設定を直接使う場合だけ `virtual-avatar-connect-desktop.exe C:\path\to\conf.toml` のように明示してください。この場合はconfの指定値または従来の既定 `127.0.0.1:57000` を維持します。

初回画面では用途別の構成を選んで新規workspaceを作るか、既存の設定を取り込めます。`conf.toml` 単独なら「TOML / ZIP」、関連ファイルもある場合は「フォルダー」を選びます。フォルダー直下の設定から参照されるFlowgraphと関連ファイルをまとめて取り込みます。直下に設定が複数ある場合は「使用する設定」で選択します。別フォルダーや絶対パスの参照先は自動収集されません。

書き出したプロファイルZIPも「TOML / ZIP」で取り込めます。自分でZIPを作る場合は `conf.toml` と関連ファイルの相対構造を維持してください。bundleはFlowgraphを含む実行構成なので、自分で作成したものか信頼できる提供元のものだけを使用します。

プロファイルZIPは圧縮後32 MiB、展開後の合計64 MiB、1ファイル16 MiB、最大1024ファイルまでです。書き出しでも上限を確認します。超える場合は、共有する構成から不要な関連ファイルを外して再度書き出してください。失敗しても元のプロファイルは変更しません。

フォルダー取込では、参照されたFlowgraphフォルダー内の現在の用途登録も保持します。認証情報用の `credentials`、作業用の `tmp.local`、退避済みの `flowgraph.disabled`、バックアップや途中処理の記録は収集しません。元のフォルダーのファイルは変更しません。

配信AIまたはデスクトップAIを選んだ後は、**AIパートナー**（機能目次の「AIの導入・基本設定」）でAIの役割、OpenAI model、API key、観測対象を設定します。「保存して再起動」でactive profileへ反映されます。GUIへ入力したAPI keyは `conf.toml` ではなくprofile内の `credentials/openai-api-key.txt` へ分離し、workspace bundleには含めません。

「保存のみ」は設定を保存し、稼働中のAIへの適用は再起動時に行います。出力上限・ストリーム出力・入力待ち時間などの既存値と、独自に編集したツール・身体表現グラフを保持して保存します。Studioなどで関連ファイルが変更されていると保存を拒否し、入力は残ります。「保存内容を読み直す」は未保存入力を破棄する確認を挟むため、必要な入力を控えてから最新内容を読み直してください。独自配線の送出先を基本設定から安全に変更できない場合は、Studioで該当の接続を編集します。

既定で以下が有効になります。

| 項目 | 値 |
|---|---|
| Web UI | <http://127.0.0.1:46000/gui/> |
| Control API | <http://127.0.0.1:46000/api/v1/control/> |
| WebSocket | `ws://127.0.0.1:46000/ws/control` |
| Input 投稿 UI | <http://127.0.0.1:46000/input> |
| OBS 字幕 | <http://127.0.0.1:46000/output/subtitles-1> 等 |

通常の同一PCからの接続は認証不要です。認証必須に設定した接続先では、画面左の「このVACの接続認証」に、そのVACの認証トークンを入力します。自動生成されたトークンは `<runtime_dir>/control-token.txt` にあります。ブラウザーがこのファイルを自動で読むわけではありません。

### ホームに表示されるもの

ホームの「動作モード」には、設定したモードが名前付きのボタンで並びます。「✓ 使用中」が現在のモードです。切り替えたいモードのボタンを押すと、切替内容を確認して実行します。アプリの終了要求や機能の許可範囲の変更を含む場合は、確認欄で内容を確認して「確認して切り替える」を押します。

モード名や個数は利用者の設定によって変わります。「通常」「配信」に固定されていません。未設定でもVACは利用でき、連携アプリをまとめて操作したい場合などに「動作モード」から追加できます。画面上部の操作対象と接続先を確認してください。切り替わるのは現在接続しているVACで、別のVACには反映されません。

左の「機能を探す」から機能名で探すか、「全項目を展開」で各画面の操作項目を一覧できます。ホームの「追加した機能」は既定の追加先にある構成の一覧です。別の場所へ取り込んだ構成や自作グラフも含めるには、機能目次の「保存された全構成」を開きます。

ホームは単一の配信用構成を仮定した設定画面ではなく、active profileで現在利用できる機能の概要です。AIパートナー、音声入力、Twitch入力は、confとロード済みFlowgraphから実際のインスタンスを列挙します。複数のpersona、音声デバイス、Twitch購読先を同時に構成できます。

- AIパートナーの表示名は`[[ai.personas]].display_name`で設定します。未設定時だけpersona IDを表示します。
- 音声入力とTwitch入力の表示名は各Ingress nodeの`properties.label`で設定します。これはGUI用の名前であり、データの接続契約ではありません。
- Twitch OAuthはアカウント権限、Twitch入力ノード（`flowgraph.ingress.twitch`）の `properties.channels`は受信先です。認証したアカウント自身のチャンネルへ固定されません。
- OAuth tokenの外部検証は連携画面を開いたときだけ行います。ホームは実際のIRC/EventSub worker状態を表示し、定期更新のたびにTwitch APIへ問い合わせません。
- データ配線と有効化条件の正本はFlowgraphです。ホームの操作から構成確認はFlowgraph Studio、資格情報の管理は連携画面へ分けて移動します。

「利用状態」のTwitchコメントは、チャンネルへの参加と受信を確認します。コメントを字幕にせず、自動化の入力だけに使うこともできます。「画面出力」には構成済みの経路数と出力履歴の宛先を表示します。処理が途中で止まる場合はFlowgraph Studioで実行経路を確認し、OBSに表示されない場合はブラウザーソースのURLと出力先を確認してください。

### 音声入力のソフトミュート

ホームまたはライブの「音声入力」スイッチをOFFにすると、VAC内部で音声認識結果を破棄します。
OS、音声デバイス、VCアプリのミュート状態は変更せず、Vosk / Whisper workerも維持するため、
再開時にモデルの再読込は発生しません。managed profileではこの状態を保存し、VAC再起動後も維持します。Control APIでは
`PUT /api/v1/control/voice-input`へ`{"muted":true}`または`{"muted":false}`を送ります。

使用中の音声入力がない場合、この操作は入力開始後の受付を設定するだけで、マイクや音声認識を起動しません。現在の変更対象は操作中のVACです。次回起動用の状態は管理設定の保存先を共有するVACで共通となり、既に稼働中の別VACの受付は切り替わりません。
保存できなかった場合も現在の受付変更は反映されます。画面内の警告を確認し、保存先の問題を解消して「現在の受付状態を再保存」を押してください。API応答の`persistence_error`がある場合も、現在の`muted`とは別に次回起動用の保存が失敗したことを示します。

### 配信前セルフテスト

ライブ画面の「配信前セルフテスト」では、字幕、個別の音声合成、コメント読み上げ、AIアバター経路を分けて実動作確認できます。

- 「音声を含む一括確認」は、字幕、chat以外の有効なTTS、構成済みのコメント字幕/TTS、AIアバターを順番に検査します。音声を直列再生して重複を避け、途中で失敗しても残りを確認して失敗箇所をまとめて表示します。
- 「字幕を2秒表示」は`user`と`ai-synth`へテスト字幕を出し、自動で消去します。AI観測とFlowgraph購読には流さないため、AI応答やTTSを誤発火させません。
- 「テスト音声を再生」は選択した有効な`flowgraph.tts.speak`経路を実行し、合成だけでなく音声再生の完了または失敗まで待ちます。対象経路に口パク設定があれば同じ経路で動作します。
- 「字幕と音声を確認」は監査済みの`chat`購読ノードを1回だけ発火し、`chat-synth`字幕への到達とchat lane TTSの再生完了を同じprobe IDで確認します。Twitch IRC受信は偽装せず、AI観測にも流しません。
- 「動作を確認」は設定したUNMF/Z keyと起動中のUNAvatar Rendererを照合し、受信frameと適用frameの両方が増えた場合だけ成功とします。

成功後は配信前チェックを再取得し、TTS再生と字幕データ到達を`準備完了`へ更新します。一括確認は実際のTwitch受信、マイクSTT、AI会話を偽装しないため、これらの最終確認は別途必要です。音声テストは実際にスピーカーへ出力するため、配信開始前に実行します。

音声認識の表示には、設定したengineに加えて実際に稼働中のbackendが出ます。
`whisper / vulkan`ならVulkan worker、`whisper / cpu`ならGPU初期化失敗後のCPU fallback、
`vosk / vosk`ならVosk単独です。複数のVoice Ingressが同時稼働している場合は、比較試験でない限り1経路へ絞ります。

### プロファイルの退避

設定画面の「管理プロファイル」では、次の区別を確認できます。

| 表示・操作 | 対象と結果 |
|---|---|
| このVACで使用中 | この画面から操作しているVACが読んだプロファイル |
| 別のVACで使用中 | 同じ保存先を使用している別プロセス。「更新」で再取得 |
| 次回起動 | 次に引数なしで起動するときに選ばれるプロファイル |
| 次回起動に設定 | 次回の選択だけを変更。稼働中のVACはそのまま |
| 内容編集 → 保存 | そのプロファイルの設定ファイルを保存。実行中への適用には再起動が必要 |
| 切替して再起動 | このVACを終了して、選んだプロファイルで起動 |

「保存先」を開くと実際の設定ファイルを確認できます。同じプロファイルを複数VACが使っている場合、保存内容は共有されますが、稼働中の各VACが自動で一斉に切り替わるわけではありません。

設定画面のプロファイル一覧から「書き出す」を選ぶと、再取込可能な
`*.unvac-profile.zip`を保存できます。実行に必要な設定、Flowgraph、辞書、OBS用resourceを含み、
OAuth/API credential、`*.bak`などの編集履歴、`flowgraph.disabled`は含みません。
用途名と構成ファイルの対応を保存した `.flowgraph-purposes.json` がある場合は、その現在の登録も含みます。用途の過去履歴・途中取込記録は持ち運びません。
TOMLにinline secretが残っている場合は書出を拒否するため、credential storeへ移してから再実行します。

削除したプロファイルは同じ画面の「削除済みプロファイル」から復元できます。元のIDに戻すため、同じIDのプロファイルが存在する場合は上書きせず停止します。復元しただけでは起動しません。復元後に保存先と内容を確認してから、利用するVACで切り替えてください。稼働中のVACが使用しているプロファイルは削除できません。

このZIPは共有用であり、認証情報や編集履歴を含む完全な環境バックアップではありません。更新前の環境へ戻すための退避は、[移行ガイドのバックアップ手順](v1-to-v2-migration.md#1-バックアップ)を参照してください。

## 3. 使いたい機能を追加する

### Twitch配信支援から始める（AIなし）

1. 新規作成では「Twitch配信支援（AIなし）」を選びます。通知とクリップ紹介の構成が最初から入るので、この2つを追加し直す必要はありません。ホームの「追加した機能」で確認し、手順3へ進みます。
2. 既存プロファイルへ機能を足す場合は、Flowgraph画面の「機能を追加・管理」を開きます。追加済みの一覧を確認し、まだない機能の「追加内容を確認」を押します。追加先と対象ファイルを確認して追加してください。複数のVACを開いている場合は、接続中のVACとプロファイルを先に確認します。
3. 連携画面の「Twitchの基本設定」で配信者のログイン名を入力します。専用ボットを用意していなければ「投稿にも配信者を使う」を押せば、配信者自身の名前で通知を投稿できます。専用ボットを使う場合だけ、投稿用にそのログイン名を入力します。「Twitch設定を保存」を押します。「適用待ち」と表示された場合は、処理を止められる時点でそのVACを再起動します。
4. 「Twitch接続」で配信者用・投稿用の認証をそれぞれ進めます。同じアカウントを使う場合も、両方の認証状態を確認してください。ブラウザーでは認証するアカウントを確認してください。標準の認証情報は同じPCのVAC間で共有され、別アカウントへの再認証・解除は他のVACにも影響します。
5. 通知・クリップ紹介を画面に出す場合は、ライブ画面の「出力管理」で「表示する出力チャンネル」に `stream-alerts` を入力し、「OBS Template Effects」の「URL」を押してコピーします。OBSのブラウザーソースへ貼り付けてください。これはTwitchの配信者名ではなく、Flowgraphの画面出力先です。URLの変更だけでは既存のOBS設定は変わりません。別VACのURLと取り違えないようにします。
6. ここまでで標準構成の準備は完了です。次のチャネポ交換などで、チャット通知とOBSの画面表示を確認します。クリップ紹介は下記のコマンドで試せます。通知が来ない場合はホームの利用状態とログを確認してください。保存・認証の完了と、実際の通知が届くことは別々に確認します。

標準構成ではFlowgraphの編集や数値ユーザーIDの入力は不要です。通知の投稿先は受信イベントの配信チャンネル、投稿者は投稿用に認証したアカウント、画面の表示先は `stream-alerts` です。独自のグラフを取り込んだ場合や出力先を変える場合に、Flowgraphで配線・値を確認します。

この構成では、配信者の認証を通知の受信に、投稿用アカウントの認証をチャットへの書込みに使います。設定内の `broadcaster` / `moderator` はそれぞれの資格情報の名前です。AIの人格やモデルの名前ではなく、AIパートナーを作成する必要もありません。

クリップ紹介は配信者またはモデレーターがチャットで `!rc ログイン名` または `!randomclip ログイン名` と送って試せます。OBSのブラウザーソースで映像と音声の両方を確認してください。コマンドは実際のチャット・画面への出力を伴うため、テストするタイミングで実行します。

複数VACで同じTwitch通知の構成を動かすと、それぞれが処理します。プロファイルを複製した後は、どのVACを通知担当にするかを決め、使わない側でも同じ通知構成を稼働させたままにしないでください。次回起動プロファイルの変更だけでは、既に稼働しているVACの処理は止まりません。

### 読み上げ・AIを追加する

「入力した文章を読み上げる」はVOICEVOXを使う構成です。機能カードの「必要なもの」を確認し、エンジンの起動・接続先・話者を設定します。AIを追加する場合だけ、「AIパートナー」でAIの設定へ進みます。

用途から追加した構成も通常のFlowgraphです。Studioでノード・配線・値を編集でき、専門的な構成へ発展させられます。ファイル一覧と画面に表示された保存先を使い、作業フォルダーへのコピーだけで管理プロファイルへ追加できたと判断しないでください。

### 編集・共有・取り消し

- 編集後は「保存」を押し、適用結果と診断を確認します。保存時の再読込は現在の処理へ影響します。「Web入力の変更を反映するには再起動が必要」と出た場合は、そのVACの再起動後に入力を試します。
- Studioの「ファイル操作」→「ZIP書き出し」は、選択範囲または現在のファイルの構成を書き出します。この経路では画像・音声・辞書などの素材は含まれません。
- 構成と素材をまとめる場合は、「機能を追加・管理」の対象ファイルで「共有に必要なものを確認」→「候補のファイルと素材を書き出す」へ進みます。参照先の構成を確認し、同梱する素材だけを選んで書き出します。複数ファイルを起点にする場合は「保存場所を問わず全構成を表示」で対象を選び、共有範囲を確認します。プロファイル全体を持ち出す場合は、プロファイル管理の「書き出す」を使います。
- この構成ZIPを別の環境で使う場合は、取込先のVACとプロファイルを確認し、Studioの「ファイル操作」→「ZIP読み込み…」で選びます。追加先の初期値は `imported` です。「内容を確認」で構成と素材の保存先を確認してから「取り込んで保存・適用」を押します。取込後は「機能を追加・管理」の「保存場所を問わず全構成を表示」、またはStudioのファイル一覧から編集できます。Twitch認証など接続先固有の準備は別途必要です。
- 削除前には依存する構成と対象ファイルを確認します。関連する別ファイルや認証情報まで一括削除される操作ではありません。 残るファイルが使うパッケージの所属定義は削除できません。診断に表示された参照元を確認し、定義を残すか、必要なファイルの整理を先に行ってください。
- ZIP追加が途中で失敗した場合は、Studioの「途中失敗の記録」で保存状況とバックアップを確認します。削除したグラフは機能目次の「Flowgraphを履歴から復元」から確認できます。用途ZIPの取込は、用途管理の「共有・取込」で「過去の取込・途中で止まった取込」を開きます。保存結果を確認してから復旧し、同じZIPの取込を繰り返さないでください。

「機能を追加・管理」の「用途を管理する」では、複数の構成ファイルを名前でまとめられます。テンプレートを追加すると用途名も登録されます。既存の構成は全構成一覧で選び、用途名を付けて保存してください。

- **用途と構成**: 名前や構成の組合せを編集します。「構成を編集」から通常のStudioへ進めます。
- **共有・取込**: 用途を選んでZIPの構成と同梱素材を確認し、保存します。取り込む側では用途ZIPと取込先フォルダーを選び、内容を確認して登録します。
- **履歴・復元**: 登録の保存履歴、構成ファイルの撤去記録、途中取込の復旧を確認します。

「登録を外す」は用途名の登録だけを外し、グラフを残します。ファイルも外す場合は「構成ファイルへの影響を確認」から、他の用途の参照と残る構成を確認し、復元記録を残して撤去します。撤去・復元は保存内容の変更です。実行への反映はStudioで再読込し、Web入力などの変更で再起動が案内された場合は対象VACを再起動してください。

編集中や共有内容の確認中は、保存または取消まで作業の切替を止めます。同じ構成フォルダーを使うVACでは用途一覧も共有されるため、表示中の保存先を確認してください。

素材の保存場所と共有範囲の詳細は[Flowgraphの構成と同梱素材](flowgraph-composition.md#13-同梱素材をグラフから読み込む)を参照してください。

## 5. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 初回画面で「開始する構成を取得できません」と出る | 「構成一覧を再取得」を押す。入力した名前と選択済みの取込ファイルは保持される。既存設定の取込・保存済みワークスペースの「開く」も引き続き利用できる |
| GUI を開くと「ビルド手順を案内する HTML」が出る | 配布物なら同梱ファイルの欠落を確認し、完全な配布物を展開し直す。ソースからの起動なら末尾のビルド手順を実行 |
| 接続認証エラー、または `/api/v1/control/*` が 401 | 「このVACの接続認証」で接続先のトークンを設定。APIを直接使う場合は `Authorization: Bearer <token>` を付ける |
| Flowgraph の diagnostics に「型不一致」 | edge の source / target の型が違う。SocketType の表記は [node-catalog.md](./node-catalog.md) を参照 |
| Twitch の OAuth が始まらない | 連携画面の「Twitchの基本設定」を保存・適用してから、「Twitch接続」で対象アカウントの認証を開始 |
| Vosk DLL が見つからない | 配布物をDLLも含めて展開し直す。ソースビルド時の指定は `conf.example-voice.toml` を参照 |
| 初期プロファイルで `resources` がないというログが出る | 任意の静的素材置き場に関するログ。内蔵通知画面とは別経路。独自素材を `/resources/` で配信する場合は、プロファイル内の `resources` に置いてVACを再起動 |

## 開発者向け：ソースから起動する

配布物を利用する場合、この節の作業は不要です。ソースのビルド要件と配布構成は [xtask](xtask.md) を確認してください。

```powershell
cd gui
npm ci
npm run build
cd ..
cargo build --release --features embed-gui --bin virtual-avatar-connect-desktop --bin virtual-avatar-connect-cli
.\target\release\virtual-avatar-connect-desktop.exe
```

Whisper workerを含む配布構成は `cargo xtask release-build --variant portable` で生成します。通常のCargoビルドだけでは外部worker本体を生成しません。ソースからの初回起動もユーザープロファイルストアを使用します。検証では既存の常用設定と区別してください。

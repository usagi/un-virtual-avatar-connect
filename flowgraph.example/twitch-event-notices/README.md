# Twitchイベント通知

EventSubで受けたチャネポ交換、フォロー、サブスク、再サブスクの共有、サブギフト、被Raidを、モデレーターのチャット投稿とアニメーション付き画面通知へ接続する汎用例。個人名・報酬ID・認証情報を含まない。

## 接続

- `broadcaster` token key: 配信者本人。`channel:read:redemptions`、`channel:read:subscriptions`、`moderator:read:followers` が必要。
- `moderator` token key: 通知を投稿するアカウント。`user:write:chat` が必要。送信者IDはトークン検証から取得する。
- OBSブラウザソース: UNVACのWebサーバーの `/obs-template/effect?channel=stream-alerts&limit=100`。背景は透過。通知は約6.5秒ずつ順番に表示する。

既にEventSub ingressがある場合は、その出力から通知ノードへ分岐する。同じイベントを複数の通知ノードに渡さない。例全体を既存購読と重ねて導入すると二重通知になる。

## 文面と用途

`flowgraph.twitch.event_notice` の `templates` はイベント型をキーとするJSONオブジェクト。`{user}`、`{reward}`、`{count}`、`{months}`、`{url}` を使用できる。空文字を指定した型は通知しない。文面・送信先・画面表示はFlowgraphで変更でき、特定の配信者やキャラクターには依存しない。

チャネポ通知は交換の受付記録であり、ズームなどの演出が成功したという通知ではない。ギフト由来の個別サブスク通知は抑え、ギフトの総数を通知する。匿名ギフトは匿名表示を維持する。

Raid紹介は受信した配信者名、人数、チャンネルリンクを使用する。Twitch公式Shoutout、直前のゲーム情報取得、クリップ再生はこの例には含まない。

## 再配信と失敗

イベントIDでノード存続中10分・最大4096件の重複を抑止する。再起動を越える永続的な重複抑止ではない。チャット送信失敗はエラー分岐に記録し、自動再送しない。画面通知はチャット送信の成否とは独立している。

ブラウザを開く前の通知は再生しない。表示待ちは最大100件。上限超過分は画面表示を省き、ブラウザコンソールへ警告する。OBSでブラウザソースを非表示時に終了する設定にすると、その間の通知は表示されない。

Streamlabsなどとの併用中は双方が通知する可能性がある。既存サービスの無効化は自動では行わない。
